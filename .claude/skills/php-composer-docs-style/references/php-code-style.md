# PHP-код в примерах документации (PSR-12)

Все PHP-примеры в документации пакета оформляются по PSR-12 (Extended Coding
Style Guide, php-fig.org). Это те же правила, по которым должен быть написан
и сам исходный код пакета — примеры в документации не должны расходиться со
стилем кодовой базы.

## Базовые правила файла

- Файл начинается с `<?php`, короткие теги (`<?`) не используются.
- Сразу после открывающего тега — `declare(strict_types=1);`.
- Объявление `namespace` идёт после `declare`.
- Кодировка UTF-8 без BOM, окончания строк — Unix LF.
- Закрывающий тег `?>` не используется в файлах, содержащих только PHP-код.
- Файл содержит только один класс/интерфейс/трейт.
- Файл заканчивается одной пустой строкой, без хвостовых пробелов в конце строк.

## Отступы и длина строк

- Отступ — 4 пробела, табы не используются.
- Жёсткого лимита длины строки нет, но мягкий лимит — 120 символов; желательно
  укладываться в 80 символов на строку.
- Один statement на строку.

## Namespace и use

`use`-конструкции группируются по корневому namespace и разделяются пустой
строкой:

```php
<?php

declare(strict_types=1);

namespace Vendor\Package;

use Vendor\Package\Contracts\CacheProviderInterface;
use Vendor\Package\Exceptions\InvalidConfigException;

use Psr\Log\LoggerInterface;
```

## Классы

- `extends` и `implements` указываются на той же строке, что и имя класса.
- Открывающая фигурная скобка класса — на отдельной строке, закрывающая —
  на отдельной строке сразу после тела класса.
- Каждое свойство и метод объявляют видимость (`public`/`protected`/`private`) явно.

```php
<?php

declare(strict_types=1);

namespace Vendor\Package;

class CacheManager implements CacheProviderInterface
{
    private LoggerInterface $logger;

    public function __construct(LoggerInterface $logger)
    {
        $this->logger = $logger;
    }

    public function get(string $key): mixed
    {
        // ...
    }
}
```

## Методы и функции

- Открывающая скобка метода — на отдельной строке (в отличие от управляющих
  конструкций, см. ниже).
- Указывай типы параметров и возвращаемого значения везде, где это возможно —
  документация пакета должна учить читателя писать типобезопасный код.
- Между ключевым словом (`function`) и именем — без пробела перед скобками
  аргументов, но с пробелом после `function` при анонимных функциях.

```php
public function resolve(string $key, mixed $default = null): mixed
{
    // ...
}
```

## Управляющие конструкции (if/for/while/switch)

В отличие от классов и методов, открывающая скобка управляющей конструкции —
**на той же строке**. После ключевого слова — один пробел, без пробела сразу
после открывающей и перед закрывающей скобкой условия.

```php
if ($config->has('cache.driver')) {
    $driver = $config->get('cache.driver');
} else {
    $driver = 'array';
}

foreach ($providers as $provider) {
    $provider->boot();
}
```

## PHPDoc для публичного API

Каждый публичный класс, метод и свойство, которые попадают в reference-документацию,
должны иметь докблок — генератор reference-страниц опирается на него:

```php
/**
 * Возвращает значение из кэша по ключу.
 *
 * @param string $key Ключ кэша.
 * @param mixed  $default Значение по умолчанию, если ключ не найден.
 *
 * @return mixed
 *
 * @throws \Vendor\Package\Exceptions\InvalidCacheKeyException
 */
public function get(string $key, mixed $default = null): mixed
{
    // ...
}
```

Не дублируй в докблоке то, что уже очевидно из сигнатуры метода (типы уже
видны в аргументах) — фокус докблока на смысле параметра и побочных эффектах.

## Именование

- Классы, интерфейсы, трейты — `PascalCase` (`CacheManager`, `LoggerInterface`).
- Методы и свойства — `camelCase` (`getValue`, `isEnabled`).
- Константы класса — `UPPER_SNAKE_CASE` (`DEFAULT_TTL`).
- Интерфейсы допустимо (но не обязательно) называть с суффиксом `Interface`
  (`CacheProviderInterface`) — если это уже принято в кодовой базе пакета,
  сохраняй единообразие во всех примерах документации.

## Что проверять в примерах документации отдельно

- Пример компилируется/линтится (мысленно проверь синтаксис — не оставляй
  висячих точек с запятой, незакрытых скобок).
- Если пример показывает конфигурацию через массив, а не отдельный класс —
  это тоже валидный вариант, но не смешивай подходы в рамках одной страницы.
- Пример использует те же имена сущностей, что и остальная документация
  (не `Cache`, а `CacheManager`, если так называется класс в reference).
